# Port decisions and security review

This document accompanies the exhaustive candidate ledger. It describes the
current integration, not a claim of runtime validation. Work is still in progress.
The fixed source inputs and all repositories used are pinned in README.md and
inputs/. The only remotely read source so far is the GrapheneOS emulator build
guide recorded there. Commit-message links were read as local text, not visited.

## Target evidence

The product is `device/generic/goldfish/64bitonly/product/sdk_phone64_x86_64.mk` in
the pinned GrapheneOS platform checkout. The goldfish x86 kernel and product
makefiles consume the common GKI modules and the separate virtual-device module
set. `device/generic/goldfish/board/fstab/x86` uses conventional virtio block
volumes and ext4 for system/vendor/product/system_ext/metadata/data, with Android
file encryption, metadata-key storage and fs-verity. This establishes the current
storage target; it is not an argument that F2FS or Android's filesystem APIs can
be deleted globally. GKI configuration and source-module interfaces are retained
where they apply to this build.

The original common/build_virt.sh is taken verbatim from the supplied downstream
kernel checkout. This one build wrapper is required to execute the requested
workflow and is not a port of the GrapheneOS kernel hardening series. It builds
common distribution artifacts, builds the virtual-device distribution, then
signs external modules with the common kernel key. Dependencies are used in place, with the build/kernel adaptation below. No Android OS compilation or prebuilt import is
part of this work.

## Baseline and historical KMI

The baseline is Linux 6.18.57, not an older ACK tree relabeled as LTS. The
implementation commits are descendants of the pinned stable commit. Source
merges use the ACK/LTS common ancestor; conflicts are recorded in
`evidence/conflict-decisions.json`. A conflict-free textual merge is not accepted
as proof that a stable fix survives: additional review covers renamed files,
ABI-only reversions and changes that merged without conflicts.

Android KABI reservation/replacement annotations are removed. Real Android
vendor/OEM storage is retained because it supports runtime hooks. Structure
layouts and symbol CRCs are allowed to change. The Kleaf target disables frozen
ABI enforcement and symbol trimming. Module versioning, signing, source-module
build support and protection of signed modules' exports against unsigned
replacements are distinct from historical layout preservation and remain
available. The build/kernel dependency adaptation enables the latter independently
of trimming; original Kleaf otherwise disables it and its notrim fragment
rejects a kernel-only override.
Import-side restrictions derived from the historical KMI whitelist are not
enabled: rebuilt vendor modules may consume native LTS exports. This widens
the unsigned-module import interface relative to ACK, but does not grant module
loading authority or weaken an LTS check. All modules in this delivered SDK
workflow are signed. Module signatures are not forced by the ACK defconfig;
that remains unchanged. The module flags format is regenerated by
modpost and consumed by the loader from the same source tree.

The normalized ACK tree is an analysis artifact, not the delivered base. Its
reverse-revert attempts and their failures are recorded in ack-normalization.json;
subsequent explicit LTS restorations take precedence. In particular, native LTS
fwnode atomic flags, device probe-readiness, netfs stream lifetime handling,
tracing, device structure fields and wireless configuration guards replace ACK
layout workarounds. Blank lines left by removed reservations are also discarded.

The build must not silently weaken LTS tooling checks: modpost retains its
vsnprintf failure/truncation checks and validates object names before parsing.
Unsigned modules still taint the kernel even with protected exports enabled.
Protected exports are not a sandbox for privileged module code: all loaded
modules and registered vendor callbacks remain in the kernel trust boundary.

## Android interfaces and memory management

Incremental FS is included as its final ACK subsystem, rather than replaying
obsolete intermediate formats. `system/vold/VoldNativeService.cpp` supplies
Incremental FS services; the final filesystem includes its UAPI, integrity and
verity implementation, and packaged tests. It is additional kernel attack
surface reachable through privileged mounting and subsequent file operations.
Retaining the final subsystem includes its accumulated validation and lifetime
fixes; this does not claim that compilation validates the filesystem at runtime.

Rust ashmem is retained. ART's jit_memory_region.cpp still has ashmem fallback;
init/devices.cpp and goldfish SELinux policy name ashmem. Rust Binder, C Binder,
Binder selection, hooks, freeze/reporting extensions and their Rust support are
included. C Binder preserves the LTS transaction-lock/tmp_ref lifetime protection.
Rust Binder keeps the LTS extended-error behavior through the later ACK
TransactionInfo/Option<Error> implementation: clear extended error at transaction
entry, set it from a real source error, and avoid diagnostics for source-less
errors. New logging/netlink/freeze paths add observability and parsing surface;
they are not assumed safe merely because they compile.

Android DMA-buf per-process accounting, heap source APIs, UID/cpufreq accounting,
proc interfaces, memfd SELinux class and Landlock thread synchronization are
retained for Android runtime/configuration compatibility. The SELinux class is
policy-capability gated. `security_file_open` and `security_mmap_file` hooks run
only after the LSM permits the operation, so they cannot turn an LSM rejection
into success through their result pointer. Task-allocation-hook rejection frees
the allocated LSM blob. Fork-integrity-hook rejection follows the LTS path that
releases both siglock and tasklist_lock and cleans up scheduler state.

DMA-heap userspace allocation retains the LTS install-after-copy_to_user ordering.
The Android allocation helper validates flags and aligns size, then the ioctl
reserves an fd. The fd becomes visible only after copying the result succeeds;
error paths release the reservation and DMA-buf. The separate in-kernel helper
returning an installed fd is not used to bypass this ordering in the ioctl.

Compressed zram writeback and per-process prefetch are included: local
`system/memory/mmd/src/zram/per_process_ioctls.rs`, mmd_setup.rs and framework
CachedAppOptimizer establish actual Android consumers. The adaptation preserves
LTS write-side locking for writeback-limit stores, page-unit rounding, init-lock
protection for disk size, slot-handle capture under the slot lock, synchronous
partial-page reads and compressor cleanup. ACK's lock guards replace explicit
lock/unlock pairs; the synchronization requirement is preserved.

Scheduler proxy execution and Android scheduler hooks remain enabled by the ACK
x86 GKI configuration. The port retains the LTS core-pick-in-flight decrement,
fair reweight/vlag treatment, and migration-disabled exclusions in RT/deadline
pushability. Picking uses current rq->donor after lock-dropping operations rather
than a stale cached prev. The sched_ext adaptation retains LTS core-sibling
balancing and disable-state handling. These are substantial scheduler changes;
compilation cannot establish latency, fairness, deadlock freedom or runtime
parity. Proxy-chain migration behavior remains a specific runtime review item.

Android reclaim policies, hooks, GCMA/cleancache, page-pinner and x86 page-size
emulation are retained with the original GKI configuration. The x86 emulator
page-size implementation includes the vDSO layout, ELF page size and mmap
alignment support, not just the generic MM macros. The exact runtime necessity
of every reclaim knob and optional mode is unresolved; preserving the configured
ACK behavior is the conservative compatibility decision. This is not a claim
that every knob is exercised by the selected product.

## Filesystems, storage and graphics

DM default-key metadata encryption and its bio skip state are included. The
state is copied through block crypto fallback, so file data is not inadvertently
encrypted a second time by the metadata layer. Android vold MetadataCrypt/KeyUtil
are direct consumers. DM user and bow support Android snapshot/update behavior.
The ordinary LTS block submission, alignment and error-completion paths remain.
Zoned write-order pipelines and bulk-allocation optimizations are not required
by the conventional virtio-block SDK target and are omitted. This does not remove
LTS zoned support or its fixes.

F2FS/ext4/btrfs/netfs/fs-verity implementations remain at LTS except explicitly
ported vendor hooks/data/namespace integration and metadata-encryption state.
ACK's optional fs-verity and F2FS implementation refactors are not prerequisites
for the existing Android userspace ABI on this ext4 SDK target. Keeping LTS
preserves its complete fixes, including inode/GC locking, netfs request lifetime
and fs-verity state. An abandoned reverse-patch experiment is retained as audit
history only; it is not the final implementation.

FUSE canonical-path/BPF Android interfaces are included; vold Utils.cpp contains
FUSE-BPF negotiation and fallback. The adaptation keeps LTS split args.h,
release completion signatures, passthrough preparation, lock handling and folio
bounds. The synchronous release condition remains `auto_submounts`, preserving
the virtio-fs submount-unmount UAF fix. BPF args arrays grow to the Android
in/out counts; they are not reduced back to the upstream counts. FUSE-BPF is a
substantial privileged configuration and filesystem attack surface.

The generic VFS symbol namespace limits accidental driver use of internal
filesystem interfaces; modules are rebuilt with the matching imports. It does
not enforce a security boundary against arbitrary kernel code.

Graphics retains LTS DRM and TTM, with the Android virtio format/mapping behavior
and render-node dumb-buffer ioctls needed by Android minigbm. The new physical
AMD color-operation pipeline and unrelated TTM large-order optimizations are
omitted: the SDK virtio driver uses the existing shared-memory path. The ioctl
access flag change expands which authenticated device users can invoke these
operations, while retaining the LTS allocation and parameter validation.

## Networking and the explicit IPsec exception

Android UID/network policy interfaces, quota2/idletimer, APF netlink and vendor
hooks are retained. IPv6 `accept_ra_rt_table` is kept for per-interface routing;
the newer LTS default-router purge algorithm and references are retained across
all routing tables. BPF argument-size hardening is kept with matching source APIs
for netkit/lirc. These changes do not restore old KMI wrapper signatures.

The wireless implementation includes ACK's hwsim/NAN/PD extensions. Goldfish
uses hwsim and nl80211, and local wpa_supplicant contains NAN support. The exact
shipping use of every optional NAN operation is unresolved (the product's
Wi-Fi Direct feature declaration alone does not prove Wi-Fi Aware use). The
conservative choice is to retain the compatible simulator/source API rather
than treat an unsuccessful consumer search as proof of dispensability.

LTS S1G minimum-length checks are retained before addr1 access. Reservation
matching still checks the relevant channel context. NAN local schedule parsing
retains channel/regulatory validation, RX NSS bounds and per-slot channel-index
validation through shared parsers. The renamed hwsim_main.c explicitly receives
the LTS exact TX-info length policy, stop/RX mutex serialization, safe pending
skb dequeue and virtio receive-length clamp. Keeping the unused old file would
not have preserved these fixes in the compiled driver.

ACK commits `4661ae54e4e454db36bb836dbb75b75a455fe92b` and
`e6e959238f93421004a8fc03fabc50b06bc70bc5` revert upstream SPI uniqueness and its
zero-SPI follow-up because Android IPsec tests break. The local
`packages/modules/Connectivity/tests/cts/net/src/android/net/cts/IpSecManagerTunnelTest.java`
lines around 680–696 explicitly reserve the same SPI for different local/remote
destination addresses; XfrmController and IpSecService implement the API.

The port does **not** use the complete ACK revert. It keeps the LTS allocation
loop, rejects SPI zero (which otherwise creates a byspi use-after-free), retains
atomic lookup/insertion under xfrm_state_lock, and retains signal checks. It
changes the duplicate check to the destination/mark/protocol/family scope used by
Android. **This weakens upstream's global SPI uniqueness guarantee.** States
with the same SPI across destinations remain possible; SPI-only lookup can be
ambiguous and packets can be misselected/dropped as described by the local
upstream commit message. This is an explicit compatibility/security tradeoff,
not a claim that the upstream fix is unnecessary. Runtime IPsec testing is not
performed under the authorized compilation-only scope.

## Limits and remaining questions

A successful build, when recorded, will verify compilation, linkage, packaging
and artifact generation only. It will not verify boot, SELinux policy loading,
Android services, signing enforcement at load time, CTS/VTS, FUSE/IncFS behavior,
proxy scheduling, zram writeback or optional networking features.

Vendor callbacks can change allocator, reclaim, scheduler, networking and power
behavior, including bypassing ordinary paths. They are privileged kernel code;
adding the interfaces increases the audit surface even when no callback is
registered. Keeping them is required by the requested vendor customization
priority, not evidence of a sandbox or permission boundary.

Protected-host pKVM/Gunyah/GenieZone, physical SoC device-assignment, physical
storage/GPU/audio/display/charger additions, and other architecture implementations
are excluded from this x86 SDK port. The platform includes virtualization
userspace globally, so absence of a goldfish-specific reference is not proof
that virtualization is irrelevant. Ordinary upstream KVM remains; protected-host
and protected-guest behavior is outside the ordinary SDK/QEMU guest target and
has not been validated. A future platform expansion must revisit these decisions.

## Subsequent source and build review

Wrapfd is included and enabled by the ACK x86 configuration. The pinned platform
contains `system/memory/libwrapfd` and SELinux wrapfd ioctl policy. It adds a
privileged device and anonymous-inode interface for restricted buffer ownership;
its correctness and SELinux enforcement are not established by compilation.

The SDK virtio-block driver receives ACK's failed-resume double-free fix in
`2d970aadc952`: null the queue pointer after freeing it. The newer LTS zoned-limit
assignment remains. Generic PCI power hooks, virtio-console capacity, plist
exports, ublk page-size handling and required VFS module namespace imports are
retained without importing physical PCI power-controller implementations.

The full-stable overlap review starts at the peeled Linux v6.18 tag, not only the
ACK/LTS common ancestor. `evidence/full-stable-overlaps.json` gives the scanned
source head, number of intersecting stable commits, every flagged literal line,
and its semantic assessment. Its rename handling covers hwsim main; the further
NAN source split is reviewed explicitly. This found and corrected a FUSE cleanup
guard and an obsolete VFIO debug-field guard. FUSE initializes dentry epoch and
allocated metadata, and frees metadata only for the configurations that allocate
it. The non-BPF 64-bit inline timestamp is never freed as a pointer.

Rust Binder preserves the newer LTS node-refcount requeue on thread exit with the
updated ACK polling API. The process argument is passed to push_work, and returned
work is dropped outside the lock. Both page insertion and shrinker unmapping
check the VMA operations and owner identity while holding the corresponding VMA
lock, retaining the LTS ownership fix. The Binder trace-removal helper is made
visible internally; LTS module filtering and event_mutex synchronization remain.

The physical ARM per-CPU interrupt-affinity backport is excluded as a complete
API/implementation set. Native LTS interrupt handlers, descriptor fields and
platform IRQ APIs remain. The retained Android pieces are wakeup diagnostics,
IRQ synchronization hooks, source-module exports and softirq-aware scheduling.
Architecture/device-specific hook headers and their registry exports are pruned
with the associated excluded implementations. The DT reserved-memory bootloader
`debug_kinfo` driver is also excluded from this SDK guest.

The media Kconfig prompt change is required even for this target: without it,
the ACK's disabled TV/radio/SDR/test settings are invisible and defaults silently
enable a large collection of modules. Restoring the prompts and the original
negative settings makes the common module configuration match the requested
workflow. The virtual-device fragment can still enable its required test/video
modules. This change removes unintended build outputs rather than adding future
physical platforms.

Kleaf's local build metadata uses `BRANCH=lts-sdk-6.18` and an empty
`KMI_GENERATION`. It does not advertise ACK's historical generation 5. The
x86 virtual-device symbol-list input serves the unchanged mixed-build staging
check: before the wrapper signs modules, it checks their imports against that
list and exports from other unsigned staging modules. Sixteen native LTS imports
are added in 4a8a3df378ad. This is a source dependency check, not a promise of
historical layouts or symbol CRCs. Strict ABI checking and trimming are disabled.

The final header review in evidence/native-api-review.json covers 80 native API
paths individually. It found a generic IRQ vendor storage field lost with the
ARM affinity exclusion; a3d555553bf9 restores only that storage. Native LTS
percpu_affinity and descriptor semantics remain. The duplicate NAN schedule
definition from integration is removed in 14e09e03364d; both copies were identical.

The hermetic toybox diff lacks -I, so objtool emits synchronization warnings.
The unchanged tools/objtool/sync-check.sh was independently executed with
SRCARCH=x86 and PATH=/usr/bin:/bin (GNU diff) on 2026-10-22 and returned 0 with
no output. This checks the headers that the hermetic warning could not compare;
it is not a claim that the hermetic check itself succeeded.


## Required build dependency adaptation and signing

The build/kernel project starts at `38e2a76ecb0257fe1f27b0078cd9169191601ec7`.
Its delivery branch `port/android-6.18-sdk-audit` changes only the module-list
configuration helper and `kleaf/impl/defconfig/notrim_defconfig` in `2142663d`.
Original Kleaf both conditioned MODULE_SIG_PROTECT_LIST on KMI trimming and
asserted MODULE_SIG_PROTECT=n in a final fragment. That coupling prevents
retaining signed-module export protection after removing historical KMI
restrictions. The adaptation configures protection whenever a protected module
list is supplied; without a list, the existing disabled default remains.
No build commands or public target names change. The kernel post-defconfig
fragment now selects only the module-signature digest.

The pinned BoringSSL headers in
`prebuilts/kernel-build-tools/linux_musl-x86/include/openssl/cms.h` explicitly
support the detached, no-attributes CMS API used by LTS sign-file and document
BORINGSSL_NO_NO_CMS as the opt-in. Its pkcs7.h documents a SHA-256-only legacy
signing subset, despite the LTS tool assuming SHA-1 for OPENSSL_NO_CMS. The
unchanged wrapper requests SHA-256 and therefore failed after both distributions
were generated. `59b5610e4fb9` opts sign-file into CMS and selects SHA-256 for
common modules too, preserving the caller's digest selection and avoiding SHA-1.
The supplied downstream `478164719e77c0b2d2dd3a8d992e116df15286f0` guard bypass
was inspected locally but not applied: it suppresses the check without making
the legacy signing API honor the requested digest. This is a build-tool
adaptation, not import of the GrapheneOS kernel hardening series. All examined
headers, implementation and commits are local to the pinned inputs; no remote
BoringSSL resource was accessed.


Further SDK source review distinguishes generic media interfaces from physical
hardware additions. `drivers/gpu/drm/drm_print.c` and its header provide the DRM
trace output/module parameter/printer API even for virtio graphics. These and
init/cleanup are retained; LTS DRM unplug/register-failure synchronization remains.
The LTS trace_array_printk rejects a NULL array, and core-init failure calls the
matching cleanup. Tracing adds diagnostic data exposure to authorized tracefs
readers; no runtime access-control validation has been performed.

The virtual-device target explicitly builds snd-aloop. Goldfish's module blocklist
prevents automatic loading, which does not establish that optional module use is
unnecessary. Its ACK hrtimer mode is retained for source/runtime compatibility.
The V4L2 node capacity and subdevice streams interfaces are retained with LTS
validation, including the enable/disable-stream operation checks. Exact use of
these optional media interfaces by the shipping SDK userspace remains unresolved;
they are retained conservatively because these generic modules are part of the
current target. HDR10 zero-valued metadata acceptance is already in LTS, which
also retains newer AV1/HEVC tile and reference-index bounds checks.


## Generic input, peripheral and module-source review

The final source review distinguishes generic compiled files from omitted physical
features. The native LTS HID parser remains, including long-item checks,
bounds-before-debug handling and quiescing input before teardown. ACK's generic
HID mappings for the three new input keycodes are added in `5e574340df36`:
Android `frameworks/base/data/keyboards/Generic.kl` explicitly maps usage
0x0c01CD to CONTEXTUAL_INSERT. Their diagnostics and existing UAPI constants
match. Generic SCSI dispatch tracepoints and the queue-to-device helper are also
exported by that commit for rebuilt modules of the configured subsystem.
`f9dd0aa8659c` exports the native DRM mode conversion helpers without changing
their validation. Optional runtime use of these exports is unresolved; retaining
them preserves source-module customization, with modules remaining trusted code.

ACK extcon fix `ba882210daee` is applied as `c8fb68cc017c`. Its ID is released
after unregister removes the sysfs name, preventing concurrent registration from
reusing a name before removal. The LTS release callback is empty; storage is
freed separately by extcon_dev_free, so this ordering does not introduce a new
release-callback use-after-free. EXTCON is configured, while the precise connector
use in the SDK remains unresolved. This is a conservative generic lifecycle fix,
not additional physical controller support.

`evidence/generic-source-review.json` records the examined source deltas and
specific reasons for shared power, ACPI, USB, HID, SCSI and V4L2 files. For example,
LTS already has ACK's HDR10 unknown-value acceptance; its newer AV1/HEVC bounds
checks remain. LTS xHCI already has the command-accessibility guard and retains
its newer bounce-buffer and event-validation fixes. The physical clock,
interconnect, regulator, power-domain and USB-PD extensions are omitted as
complete features with their corresponding APIs. Writable clock/interconnect
debugfs is not enabled. The SDK camera provider's Android.bp explicitly selects
ranchu QEMU/fake-camera sources and libqemud, distinguishing its implementation
from the omitted USB-camera metadata/timestamp extension. Physical camera
passthrough is not validated or claimed.


## Completion of shared memory and storage paths

`6637da622c0a` connects x86 anonymous movable allocations to the already selected
Android CMA policy using __GFP_CMA. It also preserves disable_dma32=on, whose
default leaves native LTS zones intact. Exact optional SDK use is unresolved;
the boot configuration must account for low-address DMA allocation needs before
enabling it. Protected-guest/host memory and FPU code remains excluded.

`6ac6df46589d` connects generic IOMMU DMA/IOVA hooks to their retained declarations
and initializes the IOVA vendor storage. These paths are configured in x86 GKI.
Only the hook hunks are ported; native LTS mapping/invalidation and error handling
remain. Trusted callbacks can change alignment, allocation and mapping protection;
there is no security boundary between these callbacks and kernel code. Separate
protected-host deferred-SG mapping and noncoherent architecture flush changes
remain excluded. A check of all 822 named ACK hook call sites against the port
was used to identify missing generic integration; excluded physical/architecture
hooks are accounted for separately.

`1e4401eda113` completes cleancache mount/read integration for configured ext4
and F2FS and block-device invalidation. LTS filesystem algorithms remain. Cache
hits still pass fs-verity verification before being marked uptodate; F2FS still
validates the block address before consulting the cache. The shared cleancache
wrapper rejects compound pages, leaving large-folio processing on the LTS path.
The backend is trusted kernel code, and cache lifetime/invalidation correctness
is not established by compilation. Btrfs/clustered-filesystem cache integration
is omitted for this SDK target. Existing generic pool initialization and
invalidation remain in fs/super.c and the MM page-cache paths.

The blk-crypto alignment optimization is omitted as a complete transformation:
LTS bio_crypt_check_alignment remains before I/O, so absence of ACK's relocated
bio_split_io_at check does not remove alignment validation.

`db5a87077cbc` retains the Android-visible dm-verity FEC corrected-block count,
combining ACK e9edc57adcb1 and its fix 140f47bc1113. The atomic counter increments
once after successful hash revalidation and copying the corrected block. Native
LTS fixes remain: recursion prevention (232948cf600f), failed bufio creation
handling (451cc650e40e), FEC/hash device-size checks (9a484c8149b2,
1919acc5876c), split parity-byte reading (d47281b9a447) and FEC buffer bounds
(5488d3a69d20). The SHA-256 interleaving/mempool refactor is omitted separately.
The source review found no direct use of the new count in the examined
system/fs/fs_mgr/libdm and system/update_engine files; that does not prove it
unnecessary. It is a generic device-mapper status ABI for a configured SDK
verified-storage target, so compatibility is retained conservatively.

## Additional filesystem fixes found during final review

`22157454367a` applies ACK `86daefb58da53955d746f5d0b1e9c89f2f64e6ff`.
The LTS ext4 rmdir path still held its journal transaction across dentry
invalidation. Child-dentry eviction can wait for that transaction while rmdir
waits for eviction, producing a deadlock. Close the handle before invalidation
and perform invalidation only after successful removal. This preserves the
other LTS namei changes and reduces an availability risk in the configured
casefold-capable ext4 filesystem. The earlier provisional keep-LTS path note
was insufficient and has been replaced with this source-level decision.

`c7aeaf39ed7f` applies ACK `a6c308a0fafe1e155115ad421da1050b0c574e83`.
F2FS is configured even though SDK system/data volumes use ext4. Its ordinary
dentry lookup lacked ACK's name-length and filename-slot bounds check. Reject
malformed lengths before comparing names, avoiding out-of-bounds reads from a
corrupt filesystem. The separate inline-directory conversion check is already
in LTS. These are distinct paths, so that existing check did not justify omitting
the lookup fix. Both applications have matching stable patch IDs recorded in
`evidence/explicit-code-decisions.json`. Their commit-message links were read
as local provenance text only; no linked remote page was accessed.

## Architecture-only exclusions

Candidates confined to non-x86 architecture implementations can receive a final
target-exclusion decision without deferring to a missing-consumer search. The
recorded SDK build has `CONFIG_X86_64=y` and `CONFIG_X86=y`. The top-level Makefile
maps `ARCH=x86_64` to `SRCARCH=x86`, selects that architecture's Makefile and
headers, and the crypto/CRC library Makefiles select that same architecture's
implementation directory. ARM, ARM64 and other architecture-local code is outside
this executable target. Keep those paths exactly at pinned LTS, preserving their
upstream fixes without adding ACK-only support for future platforms. This rule
does not decide a commit that also changes an unresolved shared path. Nonempty
merge resolutions are subject to the same path restriction and retain their
original patches and hunk evidence in the audit.

## POLYVAL and block scheduler follow-up

`e859afda9a8a` retains the generic and x86 POLYVAL library, HCTR2 conversion,
removal of the superseded crypto_shash implementation, and accompanying test
sources. The exact ACK candidates are in `evidence/explicit-code-decisions.json`.
This is not merely a performance refactor: the old generic implementation
explicitly warns that it is not constant-time and uses data-dependent table
lookups. The replacement uses carryless multiplication built from ordinary
arithmetic without those table lookups. Its x86 implementation checks PCLMUL/AVX
availability and `irq_fpu_usable()`, falls back to the generic implementation when
needed, and permits rescheduling between 4 KiB chunks. ARM64-specific library
code is outside the current target and was not added.

The SDK fstab currently selects AES-XTS/AES-CTS, while the Android kernel
configuration enables HCTR2 and exposes that alternative encryption mode.
Actual HCTR2 use on this SDK image is unresolved; preserving the configured
algorithm with ACK's safer fallback is a conservative compatibility decision.
The HCTR2 algorithm and encrypted-data format remain the same. The obsolete
standalone POLYVAL crypto_shash interface is removed consistently with ACK;
this is a source/API transition, not historical binary KMI preservation.
The KUnit test sources and generator are retained with the library but are not
enabled or executed by the SDK workflow. Compilation does not establish timing
behavior, vector correctness, or runtime filesystem compatibility. No linked
papers or web pages in the source comments were accessed.

`9b6a6086498e` applies ACK `5494cba9e2111f56122ebc84f85a608ba5d71ed4`.
The pinned LTS block scheduler retains a two-stage switch whose completion can
manipulate kobjects outside the elevator lock. Concurrent sysfs switches can
therefore race under the shared reader lock. Use a writer trylock for the whole
switch to prevent memory corruption and hangs. Keep the LTS nonblocking trylock
and `-EBUSY` result that prevent the kernfs/disk-deletion lock cycle. No zoned
storage feature is needed to trigger or fix this generic race.

## Physical leaf-driver scope

The specific reviews in `evidence/generic-source-review.json` distinguish leaf
drivers from shared frameworks. AMD/Intel display drivers, Cirrus amplifier
codecs, Qualcomm clock controllers and MediaTek pin controllers implement
physical devices outside the selected emu64x platform. The SDK module rules
explicitly supply virtio-gpu, goldfish transports, vkms, virtio_snd and snd-aloop.
The common configuration disables the named AMD/Intel display and Cirrus codec
drivers. ARM SMMU/GIC/firmware implementations have architecture/platform
dependencies outside the ordinary x86_64 guest. UFS controller changes are
excluded because the SDK storage topology is virtio block, even though some
generic UFS configuration options remain enabled. None of these exclusions
means that generic DRM, sound, block, IRQ, IOMMU or device-core changes can be
omitted by filename alone. Those shared paths have separate reviews, and an
unresolved shared path prevents finalizing the entire candidate.

`bf631ea74abf` adapts the newly added POLYVAL KUnit option to the later LTS
policies in `ce2a263bc57c`, `95c05443aa34`, and `c846ed5ac80f`: depend on the
library, use the explicit enable-all helper for library selection, and do not
enable the test implicitly through `CRYPTO_SELFTESTS`. This preserves the effect
of the LTS configuration fixes even though POLYVAL was not present when they
were applied to that branch.

`306c6c42db66` adapts ACK's F2FS sync-error propagation. Directory-synchronous
operations and read-only remounts return checkpoint failures instead of silently
reporting success. The unlink conflict keeps native LTS cleanup and does not
import an unrelated device-alias path. The remount adaptation clears the temporary
`SBI_IS_CLOSE` flag before handling failure, preserving the LTS cleanup behavior
that the literal ACK error branch would skip.


## Binder lifetime reconciliation

The per-commit review of ACK `b4dc66f073c721fcb82870312f017d79dfca440f`
and `f19efebeefa36474874024c698a15f4dc2d3a7bf` found an integration defect:
`binder_free_transaction()` contained two copies of the LTS transaction-lock
snapshot and temporary thread-reference acquisition, but only one release.
Commit `a658d19bb7fa` removes the duplicate. The resulting function equals the
pinned LTS implementation plus the Android free-oem-structure hook. It keeps
one protected snapshot, one acquisition, and one release. The duplicate could
leak the first reference and take a second, different snapshot while concurrent
thread exit changes the transaction. This correction preserves both LTS UAF
fixes; earlier successful builds did not detect this semantic error.

A source scan after that correction compared adjacent repeated blocks of 4–40
nonblank lines in changed C/Rust/assembly sources with both pinned input trees.
It found no additional newly duplicated blocks. This is a limited diagnostic,
not proof that all integration mistakes are absent. Binder race behavior has
not been exercised at runtime.

## Software encryption fallback forward progress

ACK `34cb3812e87a5b125ebc50a3ff7414948af70d80` fixes a recursive-submit
resource deadlock. The SDK configuration enables both
`CONFIG_BLK_INLINE_ENCRYPTION_FALLBACK` and `CONFIG_DM_DEFAULT_KEY`.
Inspection of local LTS `block/blk-core.c` establishes that `__submit_bio()`
prepares encryption while `current->bio_list` is active. Bounce bios submitted
from this context cannot drain until the current call returns. Waiting for
resources held by those bios can therefore prevent forward progress. This
conclusion does not depend on the dm-inlinecrypt example in the ACK message;
that source file is absent from both supplied kernel trees.

Commit `e2fc28947c38` adapts the rescue queue/work item to the native LTS
per-page allocator. Recursive submission uses nonblocking bio/page allocation.
On exhaustion it queues the remaining source bio, preserving the advanced
iterator and matching DUN, to the existing reclaim-capable crypto workqueue.
A partially populated bounce bio is submitted before requesting more memory;
an additional source completion reference covers each such partial submission.
Only a worker bio with no allocated bounce pages may wait for a page. Thus the
current call does not wait while retaining unsubmitted pages needed for its own
progress. The worker releases its crypto keyslot normally on return.

The ACK bulk-mempool allocation/refactoring series is not a dependency of this
adaptation. Keep LTS mempool behavior and APIs, including the newer noreserve
and kvmalloc helpers. Keep early LTS alignment validation, on-stack cipher
requests, error completion, and the Android default-key skip bit. The adaptation
can create smaller bios and schedule work under memory pressure; latency and
throughput are unmeasured. Availability under memory pressure is the intended
security benefit. No fault-injection or runtime forward-progress test is claimed.

## Additional F2FS error-path review

`98004f465e41` narrows the NEED_FSCK flag after a failed resize only when
`free_segment_range()` failed before resize metadata was changed and restored
its range counters. User-block accounting and the resize-in-progress flag are
still restored. Superblock/checkpoint failures retain the repair flag, and
corruption checks are unchanged. This is an intentional change from the pinned
LTS error policy: transient inability to evacuate the range no longer forces an
unnecessary repair. `917f7badcc2e` keeps reclaim within the requested budget;
`84641ed72ff4` limits encryption bounce cleanup to encrypted compressed writes;
`45014ef115ff` corrects the SIT/SSA order in a corruption diagnostic.

The local review also confirmed native LTS current-segment migration, GC-lock
scope, pinning-space reclamation and node-footer validation fixes. Separate
large-folio/lock-tracing and device-alias feature questions remain unresolved in
`evidence/unresolved-feature-questions.json`; their fixes have not been declared
unnecessary merely because those features are absent from the current port.

The resize change does not clear an existing NEED_FSCK indication, and it does
not bypass lower-level GC validation or checkpoint I/O error handling. The
phrase "before resize metadata changes" refers to shrinking the superblock
and filesystem geometry: free_segment_range itself can perform GC/checkpoint
I/O. Their own error state remains authoritative; the adaptation removes the
additional unconditional repair flag from this caller. No recovery behavior
has been exercised with injected I/O errors.


## Intel pKVM host-only subset

The supplied goldfish `board/kernel/x86_64.mk` installs
`board/kernel/x86_64_cmdline.txt`, containing exactly
`8250.nr_uarts=1 clocksource=pit`. In ACK, `arch/x86/kvm/pkvm.c` defines
`enable_pkvm` as a zero-initialized bool, and `vmx/pkvm_init.c` enables it through
the early `kvm-intel.pkvm` parameter. Initialization returns before setting up
the protected hypervisor when it is false. This is affirmative boot-contract
evidence for excluding the isolated protected-host backend from this SDK port.
The original ACK x86 config compiles PKVM_INTEL, but compilation does not enable
this opt-in mode. Native LTS Intel and AMD KVM remain configured.

The 56 path records cover only isolated pKVM host implementation directories
and files. Shared KVM/MM/IOMMU changes and pKVM guest support require separate
review. AVF userspace exists in the platform; no assertion is made that protected
VM behavior would work without this backend or that other boot parameters could
never request it. Such a target change requires revisiting this exclusion.

## Page-pinner adaptation and debug-buffer safety

Page-pinner remains compiled for Android configuration and vendor source
compatibility; initialization is gated by the early `page_pinner` parameter.
The selected SDK command line does not enable it. Its wider runtime necessity
remains unresolved, so absence of a found consumer is not used to remove it.
The final implementation retains the ACK initialization-before-static-key and
page-extension lifetime fixes. Higher-order freeing now uses the native LTS
`for_each_page_ext` iterator under RCU, as page-owner does. This advances even
when an extension is unflagged, handles memory-section boundaries, and records
the corresponding subpage rather than repeatedly recording the head page.

Source review also found that ACK's debug buffer could expose uninitialized
records and compute an index using the old size before a concurrent resize.
Initial and replacement buffers are zeroed; the size, index and record copy are
covered by one lock. Zero/overflowing sizes are rejected, and indexing uses the
full native size instead of the old 32-bit divisor/index. These changes prevent
invalid record decoding, out-of-bounds access during resize and division by
zero in this optional debug interface. This is a source-level finding, not an
exploit demonstration or a runtime-tested claim. Native LTS page-extension
lifetime and allocation/free logic are retained.

## Restricted vendor-hook registration

The hook core retains ACK's two-callback restricted hooks, static calls and
ordinary tracepoint hooks for source-built vendor customization. Restricted
hooks cannot be unregistered; callbacks must remain resident and are trusted
kernel code. The port retains native LTS ordinary tracepoint implementation.
For restricted hooks, the non-NULL second-callback data prohibition is now
checked under the registration mutex, closing a concurrent-registration window
that could accept a callback while discarding its data. Allocation failures
return `-ENOMEM`, NULL probes are rejected, and first-registration failure
unwinds the optional registration callback following the native LTS pattern.
These fixes address error reporting, callback state and failure cleanup without
changing permitted two-probe registration or adding a userspace interface.
Runtime concurrency/fault injection has not been performed.

The `__GENKSYMS__` include-hiding from ACK 317f0cc6bf52 is removed: suppressing
CRC changes only protects historical vendor binary compatibility, which is
explicitly excluded. Redundant per-header includes need not be restored because
the central header now includes the native tracepoint definitions for every
consumer, including genksyms. Source-built module versions are regenerated.

## Additional SDK platform hook exclusions

Remove declarations and exports whose only ACK call sites are ARM64 fault, IPI
stop or hibernation CPU-resume code. The port keeps that architecture at native
LTS and builds x86_64. Likewise, generic sched_clock's hooks and two exports are
omitted: init/Kconfig defines GENERIC_SCHED_CLOCK as a hidden boolean, no x86
Kconfig selects it, and kernel/time/Makefile builds this implementation only
under that option. Native LTS sched_clock.c is restored exactly. These are
positive architecture/build-selection exclusions, not failed consumer searches.

The SCMI performance-limit hook belongs to ARM_SCMI_CPUFREQ, dependent on
ARM_SCMI_PROTOCOL or COMPILE_TEST; neither selects that driver in this SDK
configuration. The PCI power-controller hook operates on DT power-supply
platform-device creation, not ordinary PCI/virtio discovery on the selected
ACPI SDK guest. Their absent call-site changes and remaining declarations/exports
are omitted together. Generic cpufreq and PCI power-state hooks remain.

The xHCI-platform and syscon-regmap hooks are conservatively retained: both
implementations are enabled by the supplied x86 configuration, and xHCI-platform
also has native ACPI matching. Their exact use by the SDK remains unresolved,
recorded in unresolved-feature-questions.json. A missing located consumer does
not establish that these configured, generic vendor interfaces can be removed.
The syscon hook originated for UNISOC register access; this port adds no UNISOC
controller implementation or platform enablement.

The xHCI runtime callbacks may deliberately bypass native suspend/resume when
a trusted module sets bypass. That is an explicit customization of the native
LTS power-management path and can affect availability or device state if the
callback is wrong. With no callback, the existing LTS paths and quirk-error
handling remain. System suspend, sideband handling and LTS controller fixes
are not replaced. Historical KABI declaration hiding is omitted.

The syscon hook runs after successful regmap/optional clock/reset setup under
syscon_list_lock. It receives the native config and regmap, retaining LTS
resource-size checks and error unwinding. ACK frees config.name before invoking
this callback; the port instead gives the allocated name automatic cleanup at
function exit, so it is valid during the callback on success and freed on every
error exit. Callbacks must not retain the stack config/name after return or
recursively take the syscon mutex. Runtime hook execution is not verified.

## ARM64-only hypervisor backends

GUNYAH, GUNYAH_GUEST and MTK_GZVM are explicitly ARM64-only in the pinned ACK
Kconfigs; GenieZone further documents MediaTek hardware and ARM64 support.
Their hypercall and interrupt backends live under arch/arm64. The x86 SDK does
not select those implementations. Dedicated drivers, backend UAPI/private
headers, bindings and documentation remain exactly at LTS, with each path
recorded in generic-source-review.json. This exclusion does not extend to shared
KVM, MM or IOMMU code.

There are real Android consumers: GrapheneOS virtmgr/crosvm.rs selects its
Gunyah-specific arguments only after hypervisor_props::is_gunyah checks the
hypervisor version property, and libhypervisor_backends includes GenieZone
support. Those consumers are acknowledged, not treated as missing. Their
existence on other platforms does not make an ARM64 hypervisor implementation
part of the currently selected x86 SDK kernel. No AVF runtime claim follows
from this architecture exclusion.
